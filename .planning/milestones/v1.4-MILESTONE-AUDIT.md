## E2E Flows — 5/5 COMPLETE

### Flow A: RAG Ingest → Search — ✅ COMPLETO

```
POST /api/v1/ingest (Bearer auth → 503/401/200)
  → splitText(text) → embedDocuments(chunks) → INSERT knowledge_chunks (RAG-04 metadata)
[LLM turn]
  → LLM chama search_knowledge (brain.ts bindTools + ToolNode — Phase 23)
  → embedQuery → cosine similarity → chunks formatados → LLM recebe contexto
```

REQ-IDs: RAG-01, RAG-02, RAG-03, RAG-04

### Flow B: Tool Events — ✅ COMPLETO

```
BrainRunner.run() → compiledGraph.invoke()
  → ToolMessage em TOOL_EVENTS_WHITELIST (qualify_lead, pause_session, finish_conversation)
  → event_id = threadId:tool_call_id (EVT-04)
  → eventPublisher.publish() fire-and-forget → webhook ou RabbitMQ
```

REQ-IDs: EVT-01, EVT-02, EVT-04

### Flow C: FUP Full Cycle — ✅ COMPLETO (código verificado; E2E runtime pendente — human)

```
BrainRunner.run(event)
  → upsertLead(Numero, IDLead, Name, brainType="sdr")
  → INSERT: fupEnabled=true + fupNextAt = getNextValidSlot(rawNextAt, ...)  ← Phase 26 fix
[FupScheduler background]
  → SELECT FOR UPDATE SKIP LOCKED WHERE fup_next_at <= NOW()  ← lead agora elegível
  → _generateFupMessage(): checkpointer.getTuple → histórico → llm.invoke() one-shot
  → POST FUP_WEBHOOK_URL
  → isLastFup? → ia_ativada=false, fup_enabled=false (FUP-05)
           : → fup_step++, getNextValidSlot() próximo (FUP-07)
  → eventPublisher.publish([fupEvent]) action="fup", event_id=uniqueId:fup:step (EVT-03)
```

REQ-IDs: FUP-01, FUP-02, FUP-03, FUP-04, FUP-05, FUP-07, FUP-08, EVT-03

### Flow D: Lead Responde → FUP Cancelado — ✅ COMPLETO

```
BrainRunner.run(event)
  → touchLastMessage(lead.uniqueId) → last_message_at = NOW()   ← antes do gate ia_ativada
  → resetFup(lead.uniqueId) → fup_next_at = NULL, fup_step = 0
  → FupScheduler não seleciona lead (fup_next_at IS NULL → WHERE não satisfeito)
```

REQ-IDs: FUP-06, FUP-04

### Flow E: FUP Multi-instance Safety — ✅ COMPLETO

```
[Instância A] FupScheduler._tick()
  → sql.begin(): SELECT FOR UPDATE OF l SKIP LOCKED WHERE fup_next_at <= NOW()
  → UPDATE leads SET fup_next_at = NOW() + 10min  ← marca como "em processamento"
  → commit Tx1 (lead invisível para outras instâncias durante I/O)
  → LLM + HTTP fora da transação
  → sql.begin(): UPDATE leads SET fup_step++, fup_next_at = nextSlot (Tx2)

[Instância B] FupScheduler._tick() (simultâneo)
  → SELECT FOR UPDATE SKIP LOCKED → lead já bloqueado por A → SKIP → processa outros leads
```

REQ-IDs: FUP-02 (SELECT FOR UPDATE SKIP LOCKED)
