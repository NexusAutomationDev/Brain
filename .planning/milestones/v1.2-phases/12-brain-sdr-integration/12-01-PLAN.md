<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM → ToolNode | LLM invoca tools via tool_calls; nome da tool deve ser validado antes de execução (ToolNode do LangGraph valida por nome) |
| ToolNode → DB (via ctx.sql) | pause_session e finish_conversation acessam o banco do tenant via sql injetado pelo BrainRunner |
| BrainRunner → BrainBuildContext.sql | sql é injetado pelo BrainRunner (nunca pelo LLM); thread_id vem de RunnableConfig |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01-01 | Elevation of Privilege | createPauseSessionTool / createFinishConversationTool | mitigate | thread_id lido de `config.configurable.thread_id` (RunnableConfig do LangGraph), nunca dos args da tool — implementado nas factories da Fase 11; brain.ts não precisa tratar |
| T-12-01-02 | Denial of Service | ctx.sql! non-null assertion em brain.ts | accept | BrainRunner sempre injeta sql no construtor (`new BrainRunner({ brain: sdrBrain, sql, toolsRegistry })`); o `!` é seguro; verificado em index.ts linha 67 |
| T-12-01-03 | Tampering | sdrBrain.tools[] com stubs de standard tools | mitigate | D-05: tools[] permanece com apenas qualifyLeadTool; standard tools são bound diretamente no buildGraph() sem passar pelo ToolsRegistry filtering |
| T-12-01-04 | Information Disclosure | brainOutput.fullResponse no estado LangGraph | accept | fullResponse é opaco para o handler (apenas repassado ao caller); sanitização é responsabilidade downstream; handler nunca loga fullResponse |
</threat_model>
