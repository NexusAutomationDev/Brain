<objective>
Refactor `fup-e2e.test.ts`'s 3 sequential-steps-as-separate-tests into independent tests (D-12), each responsible for its own lead/fup_config setup, so the suite honors `bun test`'s per-test independence expectation and can run in any order or in isolation. Also align `REQUIREMENTS.md`'s SUP-08 requirement text with the actual, tested production API (`toolsRegistry.enableTool(...)`) instead of the roadmap's original `ToolsRegistry.registerBrainType(...)` wording (D-11).

Purpose: The current `fup-e2e.test.ts` has 3 `test.skipIf()` blocks that share module-level mutable state (`sql`, `scheduler`, `fetchCallCount`, `lastFetchBody`) and a single `LEAD_UNIQUE_ID` row whose `fup_step`/`ia_ativada` is mutated in place — Test 2 asserts `fup_step` advances from 1 (the value Test 1 left it at) to 2, and Test 3 asserts the lead has `ia_ativada=false` (the value Test 2 left it at). Running Test 2 or Test 3 alone, or in a different order, produces false failures/passes that have nothing to do with the code under test — a classic test-isolation smell that erodes confidence in the suite and blocks safe parallelization. `enableTool()` is the established, tested API used since Phase 27 across both Brains (confirmed via `apps/brain-sdr/src/index.ts` and `apps/brain-support/src/index.ts`, both call `toolsRegistry.enableTool(brainType, toolName)`, never `registerBrainType()` directly) — renaming production code for a cosmetic requirement-text mismatch is disproportionate; the fix is updating the requirement text to describe what was actually built and verified.
Output: `fup-e2e.test.ts` with 3 fully independent tests, each creating and tearing down its own lead row; `REQUIREMENTS.md`'s SUP-08 line updated.
</objective>

    async function insertLead(uniqueId: string, overrides: {
      fupStep?: number;
      iaAtivada?: boolean;
      fupEnabled?: boolean;
      fupNextAtPast?: boolean;
    } = {}): Promise<void> {
      const { fupStep = 0, iaAtivada = true, fupEnabled = true, fupNextAtPast = true } = overrides;
      await sql!`
        INSERT INTO leads (unique_id, nome, numero, brain_type, fup_enabled, ia_ativada, fup_step, fup_next_at)
        VALUES (
          ${uniqueId}, 'E2E Test Lead', ${"5511000000001"}, ${BRAIN_TYPE},
          ${fupEnabled}, ${iaAtivada}, ${fupStep},
          ${fupNextAtPast ? sql!`NOW() - INTERVAL '1 minute'` : null}

        ON CONFLICT (unique_id) DO UPDATE SET
          fup_enabled = ${fupEnabled}, ia_ativada = ${iaAtivada}, fup_step = ${fupStep},
          fup_next_at = ${fupNextAtPast ? sql!`NOW() - INTERVAL '1 minute'` : null},
          fup_failure_count = 0, updated_at = NOW()
      `;
    }

    afterAll(async () => {
