# Applies to every `docker build -f apps/<brain>/Dockerfile .` invocation since all
# Brains share the same build context (repo root). Prevents leaking secrets, git history,
# and stale host-tree build artifacts into the Docker build context sent to the daemon.

.planning

manual

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host filesystem -> Docker build context | Files on the developer/CI host are sent to the Docker daemon as build context; anything not excluded by `.dockerignore` is readable by every stage of the build, including intermediate layers that may be cached/inspected |
| GitHub Actions runner -> Docker build | CI checks out the repo fresh (no local `.env`, no `node_modules`) but the same `.dockerignore` still applies defensively for local `docker build` usage by developers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-01 | Information Disclosure | Docker build context (no .dockerignore existed before this plan) | mitigate | Root `.dockerignore` excludes `.env`, `.env.*` (with `.env.example` explicitly re-included), `.git`, and `node_modules` from the build context sent to the Docker daemon — prevents secrets and git history from ever being readable inside any build stage or cached layer |
| T-30-02 | Tampering | Stale host-tree `dist/`/`.turbo` artifacts shadowing fresh `tsc` output | mitigate | `.dockerignore` excludes `dist`, `**/dist`, `*.tsbuildinfo`, `.turbo` so the builder stage always compiles from source inside the container, never trusts host-built artifacts that could be stale or built for a different platform/arch |
| T-30-03 | Information Disclosure | `apps/brain-sdr/Dockerfile` runner stage missing `packages/embeddings` | accept | Not a security threat — this is a functional correctness bug (missing module causes runtime crash, not data exposure). Fixed in Task 2 for availability, not confidentiality/integrity reasons. |
</threat_model>
