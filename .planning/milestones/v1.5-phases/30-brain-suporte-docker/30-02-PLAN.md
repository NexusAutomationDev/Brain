```yaml
# apps/brain-support/docker-compose.yml
# Convenience local dev/test stack: Postgres (pgvector) + brain-support juntos.
# Uso: docker compose -f apps/brain-support/docker-compose.yml up
# Reproduz localmente o mesmo round-trip usado na validação e2e da Phase 30 (D-09):
# build -> subir postgres efêmero -> subir brain-support -> testar /health e /api/v1/webhook.
#
# ATENÇÃO: este compose usa um volume nomeado isolado (brain_support_pgdata) — NUNCA aponta
# para o Postgres de produção do host (db_postgres). Para descartar o estado de teste:
# docker compose -f apps/brain-support/docker-compose.yml down -v

services:
  postgres:
    image: pgvector/pgvector:pg14
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: ${DATABASE_PASSWORD:-change-me-in-production}
      POSTGRES_DB: ${DATABASE_NAME:-brain_suporte}
    ports:
      - "${DATABASE_PORT:-5433}:5432"
    volumes:
      - brain_support_pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      timeout: 5s
      retries: 10

  brain-support:
    build:
      context: ../..
      dockerfile: apps/brain-support/Dockerfile
    image: brain-support:latest
    depends_on:
      postgres:
        condition: service_healthy
    ports:
      - "${PORT:-3002}:${PORT:-3002}"
    env_file: .env
    environment:
      DATABASE_HOST: postgres
      DATABASE_PORT: 5432
    restart: unless-stopped

volumes:
  brain_support_pgdata:
```

Key design notes to preserve exactly:
- `postgres` service listens on host port `${DATABASE_PORT:-5433}` (not 5432) to avoid colliding with the host's production `db_postgres` container, which also binds 5432 internally but on the Swarm overlay network, not necessarily host-published — using 5433 as the compose default is the safer choice regardless.
- Inside the compose network, `brain-support` connects to Postgres via service name `postgres` on port `5432` (container-internal), overridden via the `environment:` block regardless of what `.env` says for `DATABASE_HOST`/`DATABASE_PORT` — this guarantees the compose stack is self-contained and never accidentally points at `host.docker.internal` (which `.env.example`'s default targets, for the non-compose manual-run case).
- `depends_on: condition: service_healthy` ensures brain-support does not start until Postgres accepts connections, avoiding a race with `runMigrations()`'s advisory lock on first boot.
- Named volume `brain_support_pgdata` is compose-stack-local — `docker compose down -v` fully discards it, satisfying D-07's requirement that nothing persists touching production infrastructure.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker build context -> image layers | Source code, package.json, and lockfiles enter the image; must not embed secrets (no ARG/ENV with credentials baked in) |
| Container runtime user -> host | Container process must not run as root (privilege escalation surface if the container is ever compromised) |
| docker-compose network -> host network | Postgres test container must not be reachable from outside the compose network by default, and must never share a volume/port with the production `db_postgres` container |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-04 | Elevation of Privilege | apps/brain-support/Dockerfile runner stage | mitigate | `USER bun` set before `CMD` — container process runs as non-root `bun` user (ASVS L1 V10.2.1), matching the brain-sdr/brain-echo precedent |
| T-30-05 | Information Disclosure | apps/brain-support/Dockerfile — no secrets in ENV/ARG | mitigate | Dockerfile declares only non-sensitive defaults (`PORT`, `NODE_ENV`, `MIGRATIONS_FOLDER`); all credentials (`DATABASE_PASSWORD`, `API_KEY`, `WEBHOOK_TOKEN`, etc.) are supplied at container runtime via `--env-file`/`docker run -e`, never baked into the image or committed to the Dockerfile |
| T-30-06 | Denial of Service / Tampering | docker-compose.yml test Postgres colliding with production `db_postgres` | mitigate | Test Postgres uses isolated named volume (`brain_support_pgdata`) and non-default host port mapping (`5433` default) distinct from production; compose stack is fully disposable via `docker compose down -v` |
