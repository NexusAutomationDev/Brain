<objective>
Close the SUP-02/D-04 gap identified in `29-VERIFICATION.md` (corroborated by `29-REVIEW.md` WR-01): `ctx.mcpTools` is concatenated unfiltered into the tool list in `apps/brain-support/src/brain.ts` `buildGraph()`, before `search_knowledge` is appended. An MCP server exposing a tool literally named `search_knowledge` (or `pause_session`/`finish_conversation`/`respond`) would collide by name with the native tool in `bindTools()`/`ToolNode`, with undefined precedence — silently defeating the "structurally impossible to disable" guarantee required by SUP-02.

Purpose: Make the "search_knowledge can never be disabled or shadowed" guarantee hold against ALL ENV-driven inputs, not just `BRAIN_TOOLS` — `MCP_URL`/`MCP_TOOLS` is also operator-controlled ENV and must not be able to defeat it.

Output: `apps/brain-support/src/brain.ts` filters `ctx.mcpTools` against a reserved native tool name set before concatenation. `apps/brain-support/src/__tests__/unit/brain.test.ts` gains a regression test proving the collision is prevented.
</objective>
