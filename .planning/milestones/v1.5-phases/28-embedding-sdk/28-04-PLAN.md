<objective>
Wire `IEmbeddingProvider` into `BrainRunner` at both integration points identified by D-08:
embed the user's message (blocking, D-09) before `getContext()` so semantic search actually
works, and embed `profileValue` before `saveContext()` so the previously dead
`upsertEmbedding()` write path activates (closing the original MEM-03 tech debt). Add the
D-15 dimension fail-fast check in `init()`, comparing `embeddingProvider.dimensions` against
the live `vector(N)` column via `pg_attribute.atttypmod` introspection.

Purpose: This is the other half of D-16's original tech debt (MEM-03 — semantic write path
never triggered). Without this plan, `packages/embeddings` (Plan 01) and migration 0009
(Plan 02) exist but BrainRunner still never calls them for the memory-manager write path —
EMBD-05 remains unmet. The D-15 fail-fast check exists specifically because operators WILL
forget that changing `EMBEDDING_DIMENSIONS` requires a new migration (D-07) — this converts
an obscure mid-conversation Postgres error into a clear startup failure.

Output: `BrainRunner` resolves an `IEmbeddingProvider` once in `init()` (injected via
`BrainRunnerOptions.embeddingProvider` for tests, or built from ENV via
`createEmbeddingProvider()` otherwise) — same DI shape as the existing `eventPublisher`
pattern. `run()` uses it at query-time (blocking) and save-time (graceful fallback).
</objective>
