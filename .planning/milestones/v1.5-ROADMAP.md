## Milestone Summary

**Stats:** 140 commits, 158 files changed, +21.037 / -493 lines, 2026-06-29 → 2026-07-02 (~3 days)

**Gap-closure phases (from milestone self-audit):**

- Phase 31 and Phase 32 were both created after `v1.5-MILESTONE-AUDIT.md` (audited 2026-07-01, covering phases 27-30) surfaced 22 review findings (1 accepted-override critical, 9 warnings, 12 info) and 2 unresolved requirements (TECH-04, TECH-05). Rather than reopen phases 27-30, the gaps were closed as new dependent phases — Phase 31 handled the "worth a follow-up before onboarding a real client" subset, Phase 32 handled the remaining warning/info-level findings and doc/test hygiene gaps.
- Phase 32 itself needed a re-verification pass (plan 32-06) after its first verification returned `gaps_found` (6/8) — a flaky `brain-runner.test.ts` under real `.env.test` conditions and an unmarked `TECH-06` checkbox. Both closed before the phase was accepted.

**Key Decisions:**

- `IEmbeddingProvider` interface (`embed()`, `embedQuery()`, `dimensions`, `providerName`) — provider-agnostic abstraction, OpenAI adapter shipped as default, Gemini adapter added as a second real implementation to prove the interface generalizes (Phase 28)
- Migration `0009` derives `vector(N)` from `EMBEDDING_DIMENSIONS` at `drizzle-kit generate` time (not runtime) — accepted pre-production tradeoff: regenerating for a new dimension count requires manually re-adding `TRUNCATE` (Phase 28, override accepted by biellil 2026-07-01)
- `pause_session`/`finish_conversation` implemented as native closures in `buildGraph()` for Brain Suporte, not via MCP dynamic loading — reinterprets SUP-03 per D-01/D-02, confirmed as intentional deviation by the user (Phase 29)
- `RESERVED_TOOL_NAMES` guard filters `ctx.mcpTools` before `bindTools()`/`ToolNode` so an MCP server can never shadow a native tool (`search_knowledge`, `pause_session`, `finish_conversation`, `respond`) by exposing a same-named tool (Phase 29/32 — later derived from actual tool instances instead of a hardcoded literal)
- `respond` tool protected by the same append-after-filter pattern as `search_knowledge` in both `brain-sdr` and `brain-support` — a misconfigured `BRAIN_TOOLS` whitelist can no longer silently degrade every turn to a fallback response (Phase 31)
- `getEmbeddingProvider()` remains a process-lifetime singleton with no invalidation path — deliberate: embedding ENVs are fixed per container in this deployment model, no runtime-reload use case (Phase 32, D-05/D-10)

**Issues Resolved:**

- TD-03, FUP-02, MEM-03, OBS-02, D-16 (all carried over from v1.4) — resolved in Phases 27-28
- All 22 code-review findings (warnings + info) from Phases 27-30 — resolved in Phase 32
- `mock.module("@brain-pkg/embeddings")` cross-test pollution between `brain-runner.test.ts` and `factory.test.ts` — root-caused and fixed (Phase 32)
- `fup-e2e.test.ts` sequential-mutation test ordering dependency — refactored into 3 independent tests (Phase 32, D-12)

**Issues Deferred:**

- `fup-e2e.test.ts` integration run against the local sandbox DB is blocked by a pre-existing, unrelated Postgres schema-state issue (`relation "agent_state" already exists`) — out of scope for Phase 32, isolation confirmed by code inspection instead
- Nyquist validation coverage remains partial across v1.5 phases (only Phase 28 has a `VALIDATION.md`)

**Technical Debt Incurred:**

- None new. This milestone was itself substantially about paying down v1.4 tech debt and its own self-audit findings — the v1.5 ledger closes at zero known open items as of Phase 32.
