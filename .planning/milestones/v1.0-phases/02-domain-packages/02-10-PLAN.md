Root cause: .env.test sets EMBEDDING_DIMENSIONS=10 (originally chosen for FakeEmbeddings compatibility in plan 02-00), but packages/database/src/schema/tables.ts validates that EMBEDDING_DIM must be between 128 and 4096, throwing at module load time. When `bun test packages/memory` runs, it auto-loads .env.test which sets NODE_ENV=test, triggering the validation error BEFORE any tests execute.

- FakeEmbeddings from @langchain/core/utils/testing always returns [0.1, 0.2, 0.3, 0.4] (4 dimensions, hardcoded), NOT 10 dimensions as the original comment assumed
- SyntheticEmbeddings from the same module accepts { vectorSize: number } and generates content-based embeddings of exactly the specified size
- The resolution is EMBEDDING_DIMENSIONS=128 (minimum valid value) + SyntheticEmbeddings({ vectorSize: 128 }) in test files

Purpose: SC-2 (MemoryManager exercises all 3 memory layers in a single test) is blocked by this env conflict. The implementation is correct — only the test configuration is wrong.

Output: .env.test, semantic.test.ts, manager.test.ts, setup-test-db.sh aligned at EMBEDDING_DIMENSIONS=128. bun test packages/memory exits 0.
