## Gap Bloqueador: FUP-02 — fup_next_at não inicializado na ativação automática

**Wiring quebrado:**
```
Phase 25: upsertLead(brainType="sdr")
  → fup_config found, enabled=true
  → INSERT lead: fupEnabled=true, fupNextAt=NULL        ← correto mas incompleto

Phase 22: FupScheduler._tick() [fup-scheduler.ts:113-115]
  → WHERE fup_next_at <= NOW()
  → NULL <= NOW() = NULL no PostgreSQL                  ← QUEBRADO
  → Lead jamais recebe FUP
```

**Arquivos:**
- [packages/core/src/leads/lead-service.ts](packages/core/src/leads/lead-service.ts) linhas 64-72 — `.values()` no INSERT sem `fupNextAt`
- [packages/core/src/fup/fup-scheduler.ts](packages/core/src/fup/fup-scheduler.ts) linhas 113-115 — WHERE sem NULL check
- `.planning/phases/25-fup-activation/25-CONTEXT.md` D-05 — descreve intenção nunca implementada

**Correção requerida:**

*Opção A — em upsertLead() [recomendada]:*
Ao ativar FUP (`isInsert && fupEnabled`), calcular `fupNextAt = getNextValidSlot(NOW() + intervals_seconds[0], config)` e incluir no INSERT.

*Opção B — em FupScheduler._tick():*
Adicionar query separada que inicializa `fup_next_at` para leads onde `fup_enabled=true AND fup_next_at IS NULL`.
