```yaml
# .github/workflows/publish-brain-sdr.yml
# Publica o brain-sdr no DockGate registry a cada push de tag semver.
# Para adicionar brain-echo: copiar este workflow, ajustar APP_NAME e IMAGE_NAME.
name: Publish brain-sdr

on:
  push:
    tags:
      - 'v*.*.*'

env:
  APP_NAME: brain-sdr
  IMAGE_NAME: brain-sdr

jobs:
  publish:
    runs-on: ubuntu-latest
    permissions:
      contents: read

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Extract version from tag
        id: version
        run: echo "VERSION=${GITHUB_REF#refs/tags/v}" >> $GITHUB_OUTPUT

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Build Docker image
        uses: docker/build-push-action@v6
        with:
          context: .
          file: apps/brain-sdr/Dockerfile
          tags: ${{ env.IMAGE_NAME }}:${{ steps.version.outputs.VERSION }}
          push: false
          load: true
          cache-from: type=gha,scope=brain-sdr
          cache-to: type=gha,mode=max,scope=brain-sdr

      - name: Export image to tar
        run: docker save $IMAGE_NAME:${{ steps.version.outputs.VERSION }} -o image.tar

      - name: Calculate sha256 and size
        id: integrity
        run: |
          echo "SHA256=$(sha256sum image.tar | awk '{ print $1 }')" >> $GITHUB_OUTPUT
          echo "SIZE=$(stat -c%s image.tar)" >> $GITHUB_OUTPUT

      - name: Request upload URL from DockGate
        id: upload_url
        env:
          DOCKGATE_URL: ${{ secrets.DOCKGATE_URL }}
          DOCKGATE_UPLOAD_TOKEN: ${{ secrets.DOCKGATE_UPLOAD_TOKEN }}
        run: |
          RESPONSE=$(curl -sf -X POST \
            -H "Authorization: Bearer $DOCKGATE_UPLOAD_TOKEN" \
            "$DOCKGATE_URL/apps/$APP_NAME/upload?version=${{ steps.version.outputs.VERSION }}")
          echo "URL=$(echo $RESPONSE | jq -r .url)" >> $GITHUB_OUTPUT

      - name: Upload image to MinIO
        run: |
          curl -sf -X PUT \
            -H "Content-Type: application/octet-stream" \
            --upload-file image.tar \
            "${{ steps.upload_url.outputs.URL }}"

      - name: Publish latest version via DockGate
        env:
          DOCKGATE_URL: ${{ secrets.DOCKGATE_URL }}
          DOCKGATE_UPLOAD_TOKEN: ${{ secrets.DOCKGATE_UPLOAD_TOKEN }}
        run: |
          curl -sf -X PUT \
            -H "Authorization: Bearer $DOCKGATE_UPLOAD_TOKEN" \
            -H "Content-Type: application/json" \
            -d "{\"version\":\"${{ steps.version.outputs.VERSION }}\",\"sha256\":\"${{ steps.integrity.outputs.SHA256 }}\",\"size\":${{ steps.integrity.outputs.SIZE }}}" \
            "$DOCKGATE_URL/apps/$APP_NAME/latest"
```

Pontos críticos a verificar no arquivo criado:

1. `on: push: tags: - 'v*.*.*'` — trigger SOMENTE em tags (não em branches)
2. `permissions: contents: read` — menor privilégio (per D-03 + ASVS L1 V4)
3. `docker save` (não `docker export`) — preserva layers para docker load (per D-05)
4. Step "Upload image to MinIO" NÃO tem `Authorization` header — apenas `Content-Type: application/octet-stream` (per D-02 + pitfall crítico do RESEARCH.md)
5. `"size":${{ steps.integrity.outputs.SIZE }}` sem aspas — integer JSON (per D-06)
6. Todos os secrets via `${{ secrets.X }}` — nunca hardcoded (per D-03)
7. Build com `context: .` e `file: apps/brain-sdr/Dockerfile` — contexto raiz (per D-10)
8. `VERSION=${GITHUB_REF#refs/tags/v}` — remove prefixo "v" (per D-08)

Sobre o cache buildx (Claude's Discretion):
O Dockerfile tem 8 steps de build sequenciais (7 packages + 1 app) com pnpm install. O build leva estimados 5-8 minutos sem cache. Usar `docker/build-push-action@v6` com `cache-from/cache-to type=gha,scope=brain-sdr` economiza 3-5 minutos em cada push de tag subsequente. O overhead de setup é ~30s. Vale a complexidade adicional (2 steps a mais).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Secrets → workflow | Secrets injetados pelo runner; nunca expostos em logs quando usados via ${{ secrets.X }} |
| GitHub Actions runner → DockGate API | HTTP Bearer token; runner não confiável (compartilhado); token limitado a upload |
| DockGate API → MinIO presigned URL | URL presignada gerada pelo DockGate; credenciais embutidas na URL pelo MinIO |
| Tag push trigger → workflow dispatch | Qualquer committer com permissão de push de tags pode disparar o pipeline |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-01 | Information Disclosure | GitHub Secrets em logs | mitigate | Secrets referenciados exclusivamente via `${{ secrets.DOCKGATE_UPLOAD_TOKEN }}` e `${{ secrets.DOCKGATE_URL }}` — GitHub Actions mascara automaticamente valores de secrets nos logs. Nunca interpolar $SECRET diretamente em `run:` sem passar pelo env: block |
| T-18-02 | Tampering | Authorization header duplo no upload MinIO | mitigate | Step "Upload image to MinIO" usa APENAS `Content-Type: application/octet-stream` — sem `Authorization` header. URLs presignadas do MinIO incorporam credenciais na assinatura; adicionar auth header resulta em 403 SignatureDoesNotMatch |
| T-18-03 | Elevation of Privilege | GITHUB_TOKEN com permissões excessivas | mitigate | Job declara `permissions: contents: read` — princípio do menor privilégio. Workflow não precisa de permissão de escrita no repositório, criação de releases, nem acesso a packages |
| T-18-04 | Spoofing | Tag forgery — trigger indevido por branch push | mitigate | Trigger restrito a `on: push: tags: v*.*.*` — apenas push de tags semver dispara o workflow. Push de branch não dispara. Somente committers com permissão de push de tags no repo podem publicar |
| T-18-05 | Tampering | Supply chain — Actions de terceiros com SHA flutuante | mitigate | Versões das Actions fixadas em @v4 (checkout), @v3 (buildx), @v6 (build-push-action) — não usa @main ou SHA flutuante. Risco residual de breaking changes entre major versions aceito: baixo impacto operacional |
| T-18-06 | Denial of Service | Presigned URL expirada (900s) | accept | O workflow de referência obtém a presigned URL APÓS o build e save estarem completos. Builds estimados em 5-8 minutos — bem dentro do limite de 15 minutos. Se build ultrapassar 900s, o curl retorna 403 com mensagem clara — não causa corrupção de dados |
</threat_model>
