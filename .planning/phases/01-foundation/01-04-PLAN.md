# Plano 04: Corrigir Build + Gerar Migrations

<objective>
Fechar os Gaps 1 e 2 da verificação de Phase 1: corrigir a falha de build no package observability (tsconfig excludes + it.todo TS2554) e gerar os arquivos SQL de migração que o migrate.ts precisa mas que nunca foram criados.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| drizzle-kit generate | Lê o schema TypeScript do filesystem — não requer conexão de banco, não executa SQL |
| pnpm-lock.yaml | Arquivo de lockfile gerado automaticamente — conteúdo controlado pelo gerenciador de pacotes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | drizzle-kit generate | accept | O comando lê apenas arquivos TypeScript locais; não recebe input externo; output são arquivos SQL que devem ser revisados antes de aplicar em produção |
| T-04-02 | Information Disclosure | Arquivos SQL gerados | mitigate | Não incluir `DATABASE_URL` ou credenciais nos arquivos de schema; os arquivos SQL gerados contêm apenas DDL (CREATE TABLE, CREATE INDEX) sem dados sensíveis — verificar antes de commit |
| T-04-03 | Denial of Service | tsconfig exclude pattern ausente | accept | Já manifestou como blocker de build; fix restaura comportamento correto; sem surface de ataque externo |
</threat_model>

<task id="4.1" type="modify">
  <title>Fix packages/observability/tsconfig.json — adicionar exclude de test files</title>
  <read_first>
    - packages/observability/tsconfig.json (arquivo a ser modificado)
    - packages/database/tsconfig.json (padrão correto a replicar — tem "src/**/*.test.ts" no exclude)
  </read_first>
  <action>
Modificar `packages/observability/tsconfig.json` para adicionar `"src/**/*.test.ts"` no array `exclude`.

Estado atual do arquivo:
```json
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "outDir": "./dist",
    "rootDir": "./src"
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}
```

Estado final desejado (correspondendo ao padrão de `packages/database/tsconfig.json`):
```json
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "outDir": "./dist",
    "rootDir": "./src"
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist", "src/**/*.test.ts"]
}
```

Isso faz o TypeScript compilador (tsc) ignorar os arquivos `*.test.ts` durante o build, evitando os 11 erros TS2554 causados pela assinatura de `it.todo()` em `@types/bun`.
  </action>
  <acceptance_criteria>
    - `grep -c '"src/\*\*\/\*.test.ts"' packages/observability/tsconfig.json` retorna `1`
    - `cat packages/observability/tsconfig.json` contém o array `"exclude": ["node_modules", "dist", "src/**/*.test.ts"]`
    - `git diff HEAD -- packages/observability/tsconfig.json` retorna saída vazia após commit (exit 0 sem output), confirmando o arquivo está commitado corretamente
    - `cd packages/observability && bun run build` (ou `tsc`) termina sem erros TS2554
  </acceptance_criteria>
</task>

<task id="4.2" type="run">
  <title>[BLOCKING] Gerar arquivos SQL de migração com drizzle-kit generate</title>
  <read_first>
    - packages/database/drizzle.config.ts (configuração do drizzle-kit: schema path, out path, dialect)
    - packages/database/src/schema/tables.ts (schema fonte — users, memories, agentState, embeddings com PGVector)
    - packages/database/src/migrate.ts (consume migrationsFolder: './src/migrations' — necessita dos arquivos SQL)
  </read_first>
  <action>
Executar `drizzle-kit generate` dentro do package `packages/database` para gerar os arquivos SQL de migração a partir do schema TypeScript.

**IMPORTANTE:** `drizzle-kit generate` lê apenas os arquivos TypeScript do schema — NÃO requer conexão a um banco de dados PostgreSQL em execução.

**Problema com EMBEDDING_DIMENSIONS:** O arquivo `packages/database/src/schema/tables.ts` faz `parseInt(process.env.EMBEDDING_DIMENSIONS || '1536', 10)` e lança erro se o valor estiver fora de 128-4096. O `drizzle.config.ts` usa `url: process.env.DATABASE_URL!` — o drizzle-kit valida a presença de `url` ao parsear a config mesmo sem executar conexão. Definir ambas as variáveis de ambiente:

```bash
cd /root/Brain/packages/database && DATABASE_URL=postgresql://localhost/placeholder EMBEDDING_DIMENSIONS=1536 bunx drizzle-kit generate
```

O valor de `DATABASE_URL` é irrelevante para o comando `generate` (não estabelece conexão), mas deve estar presente para satisfazer a validação de config do drizzle-kit.

Se `bunx` não estiver disponível, usar:
```bash
cd /root/Brain/packages/database && DATABASE_URL=postgresql://localhost/placeholder EMBEDDING_DIMENSIONS=1536 npx drizzle-kit generate
```

O comando deve:
1. Ler o schema de `./src/schema/*.ts`
2. Criar o diretório `./src/migrations/` se não existir
3. Gerar um arquivo SQL com nome como `0000_*.sql` contendo todos os `CREATE TABLE`, `CREATE EXTENSION vector`, e `CREATE INDEX` statements
4. Gerar um arquivo `meta/_journal.json` de rastreamento

Verificar que os arquivos foram gerados antes de prosseguir.

**NÃO** é necessário executar `drizzle-kit migrate` nesta etapa — isso requer um banco PostgreSQL e é responsabilidade do script `migrate.ts` em runtime.
  </action>
  <acceptance_criteria>
    - `ls packages/database/src/migrations/*.sql | wc -l` retorna pelo menos `1`
    - `ls packages/database/src/migrations/meta/_journal.json` existe (exit code 0)
    - O arquivo SQL gerado contém `CREATE TABLE "users"` (verificar: `grep -l 'CREATE TABLE "users"' packages/database/src/migrations/*.sql`)
    - O arquivo SQL gerado contém `CREATE TABLE "memories"` (verificar: `grep -l 'CREATE TABLE "memories"' packages/database/src/migrations/*.sql`)
    - O arquivo SQL gerado contém `CREATE TABLE "agent_state"` (verificar: `grep -l '"agent_state"' packages/database/src/migrations/*.sql`)
    - O arquivo SQL gerado contém `CREATE TABLE "embeddings"` (verificar: `grep -l '"embeddings"' packages/database/src/migrations/*.sql`)
    - O arquivo SQL gerado contém a definição de coluna vector (verificar: `grep -l 'vector(' packages/database/src/migrations/*.sql`)
  </acceptance_criteria>
</task>
