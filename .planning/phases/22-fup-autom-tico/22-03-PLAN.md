| drizzle-kit push → PostgreSQL | DDL executada contra banco de produção |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-09 | Information Disclosure | BrainRunner.init() log FUP_WEBHOOK_URL | mitigate | Logar apenas `hasFupUrl: true` — nunca a URL (pode conter tokens/path sensíveis); padrão T-20-03 do EventPublisher replicado — implementado no action da Task 2 |
| T-22-10 | Tampering | LeadService.resetFup() SQL injection | accept | Drizzle ORM usa prepared statements automáticos; `uniqueId` é o IDLead do payload validado por BrainEventSchema no transport antes de chegar ao BrainRunner; sem risco de SQL injection |
| T-22-11 | Denial of Service | schema push sem controle de versão | accept | drizzle-kit push é idempotente para ADD COLUMN com DEFAULT — re-executar não causa erro; migration 0008 aplica apenas `ALTER TABLE ... ADD COLUMN` que é safe mesmo com dados existentes (DEFAULT 0) |
| T-22-12 | Tampering | FUP_WEBHOOK_URL aponta para endpoint externo | accept | URL controlada pelo operador via ENV; sem validação de domínio por design (D-03); risco residual documentado em T-22-05 (Plan 02); operador é responsável pela segurança do endpoint |
