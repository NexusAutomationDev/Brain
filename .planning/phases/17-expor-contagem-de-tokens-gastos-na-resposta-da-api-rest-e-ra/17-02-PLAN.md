<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| BrainRunner → Transport (webhook/rabbitmq) | tokenUsage é passado como número inteiro — sem PII, sem dados sensíveis |
| HTTP Response → Client | tokenUsage exposto no JSON de resposta — números de billing, não segredos |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-04 | Information Disclosure | `consumer.ts` log de tokenUsage | mitigate | Logar apenas `{ tokenUsage }` (números), nunca o conteúdo da mensagem do usuário — padrão já seguido no consumer; verificar no code review que `this.logger.info` não loga `parsed.data.Message` ou `msg.body` junto com tokenUsage |
| T-17-05 | Tampering | `IBrainRunnerLike` duck typing | accept | Duck typing é um padrão interno de isolamento de dependência; sem superfície de ataque externa — o runner real é injetado em startup, não em runtime via input do usuário |
| T-17-06 | Information Disclosure | HTTP response tokenUsage | accept | tokenUsage são números de billing (inputTokens/outputTokens/totalTokens); não contém PII, secrets, nem estado interno do grafo (T-05-03 preservado — thread_id nunca retornado) |
</threat_model>
