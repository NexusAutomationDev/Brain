<objective>
Implement D-10, the user-confirmed scope expansion of this phase (CONTEXT.md D-10 — no
formal SEED-0X ID exists for it yet; this plan cites SEED-03 in its requirements field
because D-10 deepens exactly that success criterion, "lead silencioso recebe FUP real", by
making the sent FUP message part of the conversation the LLM actually sees next, rather than
a message that only ever reached the lead via webhook and was otherwise invisible to the
Brain's own memory): `FupScheduler` now persists the FUP message it just sent into the
lead's LangGraph checkpoint, using the exact same `compiledGraph.updateState()` primitive
`BrainRunner.injectMessage()` already exposes for `POST /debug/inject-message`.

This plan is independent of Plans 33-01/33-02's seed-file work in every respect except one:
it also touches `runner.ts`, which Plan 33-01 modified first (SEEDS_FOLDER wiring) — hence
the `depends_on: ["33-01"]` and wave 2 placement, purely to avoid a same-wave file conflict.
Purpose: closes the gap where a FUP send was only ever visible to the lead via webhook and
never became part of the conversation history the Brain's own LLM sees on the lead's next
real message.
Output: extended `FupSchedulerOptions`, a new call site in `_processFupForLead()`, updated
`BrainRunner` wiring, and new/updated unit tests proving both the happy path and the
non-blocking failure path.
</objective>
