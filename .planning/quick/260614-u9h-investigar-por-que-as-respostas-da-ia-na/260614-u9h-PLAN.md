# Quick Task 260614-u9h: Corrigir salvamento de mensagens IA no banco

**Goal:** Garantir que respostas da IA sejam salvas corretamente no DB e que ambos os lados da conversa (usuário + IA) fiquem na tabela `memories`.

**Root cause:**
1. Nó `llm` em `brain.ts` retorna `{ messages: [...state.messages, response] }` — padrão não-standard com LangGraph. Deveria retornar só o delta: `{ messages: [response] }`. Isso pode fazer o `messagesStateReducer` não salvar o AIMessage corretamente no checkpoint.
2. `saveContext()` em `runner.ts` salva só `{ lastReply: reply }` — a mensagem do usuário não fica na tabela `memories`.

**Contexto arquitetural:**
- LangGraph `PostgresSaver` salva automaticamente o estado completo (msgs humanas + IA) nas tabelas de checkpoint. Isso fornece contexto ao LLM via `thread_id`.
- Tabela `memories` é para dados de perfil de longo prazo. Atualmente só tem `{ lastReply, conversationId }`.
- O resultado de `getContext()` é descartado em `runner.ts` (linha 197) — a memória de longo prazo não é usada.

## Tasks

### Task 1: Corrigir retorno do nó `llm` em `brain.ts`
- **File:** `apps/brain-sdr/src/brain.ts`
- **Change:** Linha 73: `return { messages: [...state.messages, response] }` → `return { messages: [response] }`
- **Why:** Standard LangGraph pattern — retornar só o delta, não o estado completo. `messagesStateReducer` faz o merge via ID.
- **Verify:** Build passa; teste unitário não quebra.

### Task 2: Salvar também a mensagem do usuário em `saveContext()`
- **File:** `packages/core/src/runner/runner.ts`
- **Change:** Atualizar o `saveContext()` para incluir `lastUserMessage: event.Message` no `profileValue`.
- **Why:** Ambos os lados da conversa ficam acessíveis na tabela `memories` para consulta.
- **Verify:** Build passa.
