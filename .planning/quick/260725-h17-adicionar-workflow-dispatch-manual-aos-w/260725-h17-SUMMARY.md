# Quick Task 260725-h17: Adicionar workflow_dispatch manual aos workflows de publish Summary

Adicionado trigger `workflow_dispatch` manual (com input `version` obrigatório) aos workflows `publish-brain-sdr.yml` e `publish-brain-support.yml`, permitindo disparo pela UI do GitHub Actions sem precisar de push de tag, mantendo o trigger `push: tags:` existente 100% intocado.

## O que foi feito

Ambos os workflows de publish (Docker Hub) só disparavam via `push: tags: ['v*.*.*', 'v*.*']` (migrados para Docker Hub push na quick task 260725-gme). Rodar manualmente exigia criar/mover uma tag git. Agora ambos aceitam também `workflow_dispatch:` com um input `version` (string, obrigatório).

**Task 1 — `publish-brain-sdr.yml`:**
- Adicionado `workflow_dispatch:` como irmão de `push:` dentro de `on:`, com `inputs.version` (description, `required: true`, `type: string`)
- Step "Extract version from tag" (`id: version`) passou a ter um mapeamento `env: RAW_VERSION: ${{ inputs.version }}` seguido de um `run: |` com if/else baseado em `github.event_name`:
  - `workflow_dispatch` → `VERSION=${RAW_VERSION#v}` (remove um `v` inicial do input, se presente)
  - qualquer outro evento (push de tag) → `VERSION=${GITHUB_REF#refs/tags/v}` (linha exata já existente, sem alteração)
- Commit: `90e3f1f`

**Task 2 — `publish-brain-support.yml`:**
- Mudança idêntica espelhada (os dois arquivos são near-mirrors)
- Commit: `df8f8b8`

Em ambos os arquivos: trigger `push: tags:` existente, steps `Checkout`, `Set up Docker Buildx`, `Log in to Docker Hub`, `Build and push Docker image` e o bloco `env:` de nível workflow (`APP_NAME`, `IMAGE_NAME`) permaneceram completamente intocados.

## Decisão técnica relevante

O plano original (D-03) sugeria interpolar `${{ inputs.version }}` diretamente no texto do `run:`. Optei por passar o valor via mapeamento `env: RAW_VERSION` no step, e referenciar `$RAW_VERSION` dentro do shell script — funcionalmente idêntico, mas evita colar um input não sanitizado diretamente no texto do script shell (hardening contra script injection recomendado pela documentação do GitHub Actions, já que `run:` é shell script sem escaping automático). Isso está documentado na própria PLAN.md como uma nuance esperada da Task 1/2, não é um desvio não planejado.
