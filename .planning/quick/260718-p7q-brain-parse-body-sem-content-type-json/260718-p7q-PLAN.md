# Task 260718-p7q: Parse tolerante de body no consumer RabbitMQ

## Contexto

Após o fix passive-declare (v1.6.2) o RabbitMQ conecta OK, mas toda mensagem vinda do
n8n vai pra DLQ com `Invalid BrainEvent` (`bodyKeys 0..211`). Causa: o `rabbitmq-client`
só faz `JSON.parse` do corpo quando o publisher envia `content-type: application/json`
(Channel.js L311-316). O node RabbitMQ do n8n NÃO seta esse header, então o body chega
como Buffer/string crua e o `BrainEventSchema.safeParse` recebe uma string → rejeita.

Fix: normalizar `msg.body` antes de validar — se for Buffer/string, tentar `JSON.parse`
com try/catch. Torna o consumer tolerante a qualquer publisher (n8n, scripts) que não
seta o header. Se o parse falhar, segue o valor original e o safeParse rejeita → DLQ
(comportamento inalterado para payload de fato inválido).

Decisão de deploy: **manter a tag `brain-sdr:1.6.2`** (não bumpar compose) — recompilar
a imagem 1.6.2 com o fix e recarregar na VPS via docker load. Evita re-tocar a config
do stack em produção durante a iteração.

## Task 1: Patch no consumer

`packages/transport/src/rabbitmq/consumer.ts` — normalizar body antes do safeParse.
Trocar log `bodyKeys: Object.keys(...)` por `bodyType` (sem spam de índices).

## Task 2: Build + deploy manual
